# Publicar este projeto

## Envio pelo navegador

1. Extraia o ZIP recebido. Abra a pasta interna `classificador-spam`.
2. Entre na sua conta do [GitHub](https://github.com/) e crie um repositório chamado `classificador-spam`.
3. Descrição sugerida: `Classificação de SMS em inglês com Python, TF-IDF, Naive Bayes e regressão logística.`
4. Escolha `Public` se deseja apresentar o código no portfólio. Crie o repositório vazio, sem gerar outro README ou .gitignore.
5. Na página do repositório vazio, use o link para enviar um arquivo existente (`uploading an existing file`). Em um repositório que já tem arquivos, use `Add file → Upload files`.
6. Arraste **o conteúdo da pasta extraída**, incluindo `dados`, `docs`, `tests` e `.gitignore`. Não envie o ZIP como substituto dos arquivos-fonte, nem uma pasta externa envolvendo todo o projeto.
7. Confira a lista antes de confirmar. `README.md` e `classificador.py` devem ficar na raiz. Não envie `.venv`, arquivos pessoais ou credenciais. O pacote original já está preparado sem esses arquivos.
8. Use uma mensagem de commit como `Adiciona classificador de spam e documentação` e confirme o envio.
9. Abra a página inicial do repositório: o README deve aparecer formatado. Confira se `.gitignore` entrou; se o navegador o omitiu, crie o arquivo pelo botão `Add file → Create new file` e copie seu conteúdo.

Documentação: [enviar arquivos ao GitHub](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

O `.gitignore` ajuda o Git local a ignorar arquivos; ele não impede que você selecione e envie esses arquivos manualmente pelo navegador.

## Antes de compartilhar como portfólio

- Execute o projeto e leia o código que apresentará.
- Use `--avaliar-teste` para obter a avaliação final quando estiver pronto. Depois registre os resultados no README identificando claramente o conjunto e o comando.
- Mantenha a atribuição à base pública e a informação sobre assistência de IA.
- Acrescente seu nome e contato profissional se desejar.
- Não há uma licença definida para o código neste pacote. Escolha conscientemente uma licença se desejar permitir sua reutilização. A licença da base de dados está documentada separadamente.

Para manter o projeto depois da primeira publicação, vale aprender Git no VS Code: alterações → revisão → commit → envio. Esta primeira publicação pelo navegador não exige instalar o Git.
